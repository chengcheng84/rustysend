## 2. 消息协议

### 2.1 消息类型枚举

定义以下类型（用 `u8` 表示）：

| 类型值 | 名称 | 方向 | 说明 |
|--------|------|------|------|
| 0x01 | Ping | A→B | 探测对方在线 |
| 0x02 | Pong | B→A | 响应 Ping |
| 0x03 | DeviceInfo | 双向 | 交换设备信息 |
| 0x04 | Ack | 双向 | 确认收到 |
| 0x10 | TransferRequest | A→B | 请求发送文件 |
| 0x11 | TransferAccept | B→A | 接受/拒绝 |
| 0x12 | FileMeta | A→B | 文件元数据 |
| 0x13 | FileData | A→B | 文件数据块 |
| 0x14 | Complete | A→B | 传输完成 |

### 2.2 消息结构

每条消息格式：
- **Type** (1 字节) - 消息类型
- **Length** (4 字节，大端序) - 消息体长度
- **Body** (变长) - JSON 编码的消息体

### 2.3 消息体定义

**DeviceInfo**:
```json
{
    "version": 1,
    "device_name": "My PC",
    "port": 54321
}
```

**TransferRequest**:
```json
{
    "transfer_id": "uuid",
    "file_name": "test.jpg",
    "file_size": 2097152
}
```

**TransferAccept**:
```json
{
    "transfer_id": "uuid",
    "accepted": true,
    "reject_reason": null
}
```

**FileMeta**:
```json
{
    "transfer_id": "uuid",
    "chunk_size": 1048576,
    "total_chunks": 2
}
```

**FileData**:
```json
{
    "transfer_id": "uuid",
    "chunk_index": 0,
    "total_chunks": 2,
    "data": "base64_encoded_bytes"
}
```

**Complete**:
```json
{
    "transfer_id": "uuid",
    "success": true
}
```

## 3. QUIC 证书生成

QUIC 需要 TLS 证书。实现一个函数：

**输入**: 无  
**输出**: 自签名的临时证书（有效期 7 天）

**要求**:
- 使用 `rcgen` 库生成 RSA 密钥对
- 生成自签名证书
- 配置到 QUIC 服务端/客户端

**注意事项**:
- 不需要 CA 验证（局域网信任模型）
- 每次启动生成新证书，或者缓存到本地文件

## 4. 服务端实现

### 4.1 功能
- 绑定到 `0.0.0.0:54321`
- 接受新连接
- 每个连接生成一个 Handle 任务

### 4.2 连接处理流程
1. 接收 Ping 消息
2. 响应 Pong + DeviceInfo
3. 等待 TransferRequest
4. 响应 TransferAccept
5. 接收 FileMeta
6. 循环接收 FileData，写入磁盘
7. 接收 Complete，关闭连接

### 4.3 磁盘写入策略
- 创建文件：收到 FileMeta 后创建
- 写入数据：每个 FileData 追加写入
- 关闭文件：收到 Complete 后关闭

**注意**: 按 chunk_index 顺序接收，如果不按顺序，需要缓存乱序块

---

## 5. 客户端实现

### 5.1 功能
- 连接到目标 IP:54321
- 发送 Ping，等待 Pong
- 交换 DeviceInfo
- 发送 TransferRequest
- 接收 TransferAccept
- 发送 FileMeta
- 分块读取文件，发送 FileData
- 发送 Complete

### 5.2 分块策略
- 固定块大小：1MB
- 最后一块可能小于 1MB
- 每块分配一个递增的 chunk_index

### 5.3 超时处理
- 连接超时：10 秒
- 等待响应超时：5 秒
- 超过重试次数则放弃

## 6. 错误处理

### 6.1 需要处理的错误

| 错误类型 | 处理方式 |
|----------|----------|
| 连接失败 | 提示用户检查目标 IP 和端口 |
| 握手超时 | 重试 3 次，失败后报错 |
| 拒绝接收 | 显示对方拒绝消息 |
| 磁盘空间不足 | 取消传输，提示用户 |
| 写入失败 | 取消传输，删除不完整文件 |

### 6.2 重试策略
- 握手失败：最多 3 次
- 发送失败：最多 3 次
- 重试间隔：1 秒 → 2 秒 → 4 秒

## 7. Tauri 命令

### 7.1 暴露给前端的命令

| 命令名 | 参数 | 返回值 | 说明 |
|--------|------|--------|------|
| `start_receiver` | `save_path: string` | `success: bool` | 启动接收服务 |
| `stop_receiver` | 无 | `success: bool` | 停止接收服务 |
| `send_file` | `file_path: string`, `target_ip: string` | `result: string` | 发送文件 |

### 7.2 向前端发送的事件

| 事件名 | 数据 | 触发时机 |
|--------|------|----------|
| `transfer-progress` | `{ transfer_id, percentage, speed }` | 每 1% 或每秒 |
| `transfer-complete` | `{ transfer_id, success, file_path }` | 传输结束 |
| `file-received` | `{ file_path, file_name, file_size }` | 收到文件 |

## 8. 配置项

使用 Tauri 的持久化存储保存以下配置：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `save_path` | 系统下载目录 | 文件保存位置 |
| `device_name` | 计算机名 | 显示给对方的名称 |
| `port` | 54321 | 监听的端口 |
| `chunk_size` | 1048576 (1MB) | 分块大小 |

## 9. 实现步骤（建议顺序）

1. **协议定义** (`protocol.rs`)
   - 定义消息类型常量
   - 定义各消息体结构体

2. **QUIC 证书生成** (`quic.rs`)
   - 实现临时证书生成函数

3. **QUIC 连接管理** (`quic.rs`)
   - 实现服务端绑定和监听
   - 实现客户端连接

4. **接收器** (`receiver.rs`)
   - 实现 Ping → Pong + DeviceInfo
   - 实现接收文件并写入磁盘

5. **发送器** (`sender.rs`)
   - 实现握手流程
   - 实现文件分块和发送

6. **Tauri 集成** (`lib.rs` / `commands/`)
   - 注册命令
   - 发送事件到前端

7. **测试**
   - 本地回环测试 (127.0.0.1)
   - 两台真实设备测试
